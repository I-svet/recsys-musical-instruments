# Методы и устройство решения

## Данные

[Amazon Review Data 2018](https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/), категория Musical Instruments:

- [Оценки](https://mcauleylab.ucsd.edu/public_datasets/data/amazon_v2/categoryFilesSmall/Musical_Instruments.csv): пользователь, ASIN, рейтинг и время отзыва.
- [Метаданные](https://mcauleylab.ucsd.edu/public_datasets/data/amazon_v2/metaFiles2/meta_Musical_Instruments.json.gz): названия, категории, бренды и описания.

При скачивании проверяется SHA256. Сначала данные пишутся во временный файл, затем он переименовывается.

| Этап | Взаимодействия | Пользователи | Товары |
|---|---:|---:|---:|
| Исходный CSV | 1 512 530 | 903 330 | 112 222 |
| Первый отзыв каждой пары | 1 470 564 | 903 330 | 112 222 |
| Обучение после отбора | 144 036 | 17 702 | 7 329 |
| Проверочная часть | 5 547 | 2 613 | 2 551 |
| Тестовая часть | 3 741 | 1 985 | 1 938 |
| Всего после отбора | 153 324 | 17 702 | 7 329 |

Проверяются ID, рейтинг и время. Для пары пользователь-товар остаётся первый отзыв. При одинаковой дате берётся меньший номер исходной строки. После разбиения по времени из обучающей части по очереди удаляются пользователи и товары с менее чем пятью взаимодействиями. Это повторяется, пока состав не перестанет меняться.

Полученные множества U* и I* фиксируются для проверки и теста. Внутренние ID идут по лексикографическому порядку внешних ID. Истории за пределами выбранной группы в обучение не добавляются.

Положительных оценок в обучении 125 702, в проверке 4 710, в тесте 3 094. Названия найдены для 7 324 товаров, для остальных используется ASIN. Даты известны с точностью до дня. Известно время отзыва, а время покупки неизвестно. [Проверка данных](../research/ratings_audit.json).

## Разбиение по времени

Границы взяты по 80-му и 90-му процентилям времени полной категории после удаления повторов, до отбора пользователей. Все события одного UTC-дня остаются вместе.

| Часть | Интервал UTC |
|---|---|
| Обучение | t < 2017-04-17 |
| Проверка | 2017-04-17 ≤ t < 2017-12-08 |
| Тест | 2017-12-08 ≤ t ≤ 2018-10-04 |

Рекомендации строятся на начало периода по прошлой истории. Параметры и число эпох подбираются на проверочной части. Потом модель обучается на обучающей и проверочной частях вместе. Тестовые события историю не обновляют.

~~~text
H_u(T) = все объекты с отзывом пользователя до T, независимо от оценки
C_u(T) = I* \ H_u(T)
R_u = новые объекты из C_u(T), оценённые >= 4 в периоде проверки
~~~

Все модели ранжируют один каталог. Основные метрики считаются для пользователей с непустым R_u: 2 330 на проверке и 1 702 на тесте. Если персонального сигнала нет или оценки всех кандидатов одинаковы, используются популярные товары. Пользователь при этом остаётся в сравнении. При равных оценках первым идёт меньший ID товара.

Отдельный `Recall_all_future@10` учитывает в знаменателе товары вне I*. В него входят и пользователи с положительными отзывами только вне каталога.

| Будущие положительные события выбранных пользователей | Проверка | Тест |
|---|---:|---:|
| Все события | 7 707 | 5 393 |
| Внутри I* | 4 710 | 3 094 |
| Доля внутри I* | 61,11% | 57,37% |
| Пользователи с положительными событиями только вне I* | 797 | 791 |

В Amazon есть отзывы, но нет полного журнала показов. Для товаров без отзыва релевантность неизвестна. Качество для новых пользователей и товаров, а также эффект на реальных показах не измеряются. О временном разбиении: [A Critical Study on Data Leakage](https://arxiv.org/abs/2010.11060), [Time to Split](https://arxiv.org/abs/2507.16289).

## Модели

Ω содержит наблюдаемые оценки обучающей части, X_ui = 1[r_ui >= 4], μ означает среднюю оценку этой части.

### ItemKNN

ni означает число пользователей с положительной оценкой товара i, nij число общих пользователей у i и j.

~~~text
s_ij = nij / sqrt(ni * nj) * nij / (nij + gamma), i != j
s_ii = 0
score_u = X_u W
~~~

Для каждого столбца j сохраняются k сильнейших входящих связей i -> j. gamma и k подбираются на проверочной части. При nij = 0 или ni * nj = 0 сходство равно нулю. Отбор пользователей и товаров учитывает все рейтинги, поэтому положительных оценок у товара может не быть. [Item-based CF](https://www.ra.ethz.ch/CDstore/www10/papers/519/).

### ALS для явных оценок

~~~text
r_hat_ui = mu + b_u + b_i + p_u^T q_i
L = sum_Omega (r_ui - r_hat_ui)^2
    + lambda_f * (||P||_F^2 + ||Q||_F^2)
    + lambda_b * (||b_users||^2 + ||b_items||^2)
~~~

При фиксированных товарах совместно обновляются b_u и p_u, затем так же обновляются товары. Пропуски в ошибку не входят. μ вычисляется по обучающим данным и фиксируется. Вектор z_i составлен из единицы и q_i, а theta_u из b_u и p_u:

~~~text
theta_u = solve(sum_i z_i z_i^T + diag(lambda_b, lambda_f, ...),
                   sum_i z_i * (r_ui - mu - b_i))
~~~

Задачи решаются через матричные произведения и разложение Холецкого. [Матричная факторизация и ALS](https://gwern.net/doc/ai/tabular/2009-koren.pdf), [SciPy Cholesky](https://docs.scipy.org/doc/scipy/reference/generated/scipy.linalg.cho_factor.html).

### EASE

~~~text
min_B ||X - X B||_F^2 + lambda * ||B||_F^2, diag(B) = 0
P = (X^T X + lambda I)^(-1)
B_ij = -P_ij / P_jj for i != j
B_ii = 0
score_u = X_u B
~~~

Вычисления идут в float64 через разложение Холецкого и решение систем, lambda положительна. Нормировка берётся по диагонали соответствующего столбца. Отрицательные связи сохраняются. [Статья EASE](https://arxiv.org/abs/1905.03375).

### Факторизационная машина, FM

~~~text
f(x) = w0 + sum_j w_j x_j
       + 0.5 * sum_f [(sum_j v_jf x_j)^2 - sum_j v_jf^2 x_j^2]
~~~

FM обучается на наблюдаемых оценках с MSE и L2-регуляризацией. Штраф равен λ Σθ² / P, где P означает число линейных весов и параметров факторов. Для градиентов и Adam используется PyTorch. Версия только с ID нужна для проверки пользы метапризнаков.

Взаимодействия считаются за O(k * nnz(x)). Признаки делятся на пользовательские с контекстом и признаки товара. Оценка раскладывается на две скалярные части и скалярное произведение суммарных векторов. Совпадение с прямым расчётом проверяется тестами. [Материалы FM](https://www.libfm.org/).

### timeSVD++

~~~text
d_u(t) = sign(t - mean_time_u) * abs(t - mean_time_u)^beta
h_u(t) = sum_{j in H_u(<t)} y_j / sqrt(|H_u(<t)|)

r_hat_ui(t) =
  mu + b_i + b_i,bin(t)
  + b_u + alpha_u * d_u(t) + b_u,day(t)
  + q_i^T [p_u + a_u * d_u(t) + p_u,day(t) + h_u(t)]
~~~

При пустой истории h = 0. Есть временное смещение товара, изменение смещения и вектора пользователя, дневные поправки. mean_time_u считается по обучающим данным, время в днях UTC, beta = 0.4. Минимизируется MSE, базовые и временные параметры регуляризуются отдельно по среднему квадрату параметров группы.

В H_u(<t) входят только предыдущие дни. Неизвестные дневные поправки и интервалы времени товара равны нулю. Общие смещения и временное изменение векторов сохраняются. [Временные компоненты](https://cseweb.ucsd.edu/classes/fa17/cse291-b/reading/p447-koren.pdf).

Суммы истории считаются накоплением по дням со сдвигом. Градиенты проходят к векторам истории. SVD++ с той же историей, но без временных компонентов нужен для сравнения.

KNN и EASE используют бинарные положительные истории. ALS, FM и timeSVD++ используют все наблюдаемые оценки. Пропущенные оценки не считаются отрицательными. Перед ранжированием предсказания не обрезаются до [1,5], чтобы не создавать лишние равенства.

## Метапризнаки FM

| Признак | Расчёт | Когда доступен |
|---|---|---|
| user_id, item_id | Внутренние ID | В обучающей части |
| log(1 + prior_user_reviews) | Число прошлых отзывов пользователя | До t |
| prior_user_mean_rating | Средняя прошлая оценка пользователя | До t |
| log(1 + prior_item_reviews) | Число прошлых отзывов товара | До t |
| prior_item_mean_rating | Средняя прошлая оценка товара | До t |
| item_age_days | Дни после первого наблюдаемого отзыва | До t |
| user_tenure_days | Дни после первого отзыва пользователя | До t |
| month/day-of-week | Месяц и день недели запроса | В момент t |

У пустой истории количество и возраст равны нулю, средняя оценка равна 3. Возраст отсчитывается от первого отзыва. Масштабирование настраивается по обучающей части.

События одного дня получают признаки по предыдущим дням, затем обновляют накопленные значения. Текущая оценка в свою среднюю не входит. Для проверки и теста признаки считаются один раз на начало периода.

Названия нужны для показа рекомендаций. Цена на дату сбора, salesRank, helpful votes, also_buy/also_view, текст целевого отзыва и тестовая статистика не используются. Исторических версий этих полей нет. [Поля Amazon](https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/).

## Метрики

Параметры выбираются по среднему NDCG@10. Также считаются Recall@10, Precision@10, MAP@10 и RMSE для моделей оценок.

~~~text
Recall_u@10 = hits_u / |R_u|
Precision_u@10 = hits_u / 10
DCG_u@10 = sum_{k=1..10} rel_u(k) / log2(k + 1)
IDCG_u@10 = sum_{k=1..min(10, |R_u|)} 1 / log2(k + 1)
AP_u@10 = sum_{k=1..10} Precision_u@k * rel_u(k) / min(10, |R_u|)
~~~

R_u в основной таблице непустое. При нехватке кандидатов пустые позиции дают ноль, знаменатель Precision остаётся 10. Метрики сначала считаются для каждого пользователя, потом усредняются с одинаковым весом.

Ранжируется весь C_u. Оценка на случайной небольшой части товаров может менять порядок моделей по качеству. [On Sampled Metrics for Item Recommendation](https://research.google/pubs/on-sampled-metrics-for-item-recommendation/).

Товары идут по убыванию оценки и возрастанию ID. При частичном отборе учитываются равенства на границе первых 10 мест. Дополнительно измеряются покрытие каталога, популярность и совпадение списков, доля замен на популярные товары, время, память и качество по группам активности.

Для примеров с начальным значением генератора 2026 выбирается по одному пользователю из трёх групп активности в обучающей части. Качество рекомендаций при выборе не используется.

## Подбор параметров

Диапазоны и число запусков зафиксированы до обучения. О настройке простых моделей: [анализ воспроизводимости](https://arxiv.org/abs/1911.07698).

| Метод | Параметры | Число наборов |
|---|---|---:|
| ItemKNN | k: 20, 50, 100, 200, gamma: 0, 10, 50, 100 | 16 |
| EASE | lambda: 1, 3, 10, 30, 100, 300, 1000, 3000 | 8 |
| ALS | Размерность: 16/32/64, lambda_f и lambda_b, до 40 итераций | 16 |
| FM | Размерность: 16/32/64, шаг обучения и L2, до 50 эпох | 16 |
| timeSVD++ | Размерность: 16/32/64, шаг, L2 и временной L2, интервалы 30/90 дней | 16 |

Для ALS lambda лежит в [0.01, 100], ошибка суммируется. Для FM/timeSVD++ усредняются ошибка и квадраты параметров: L2 [1e-6, 1e-1], шаг обучения [1e-4, 1e-2]. Коэффициенты выбираются по логарифмической шкале. У трёх факторных моделей один опорный набор и 15 случайных.

У FM/timeSVD++ максимум 50 эпох. Обучение останавливается после пяти проверок без улучшения. Временной коэффициент регуляризации не меньше базового. Конкретные наборы сохранены в configs/benchmark.json, генератор random.Random(2026). Размер группы при обучении: 4096 событий, у timeSVD++ истории пользователей целые. Размер выбран по времени пробных запусков. Возрастные признаки преобразуются через log(1+days).

ALS, FM и timeSVD++ запускаются с начальными значениями генератора 17, 42, 2026. ItemKNN и EASE один раз. Для каждого итогового запуска число эпох выбирается на проверочной части, затем модель обучается на двух частях вместе. Упрощённые версии получают параметры полной модели и отдельно выбирают число эпох. Заново все параметры для них не перебираются.

В таблице приведены среднее и стандартное отклонение запусков. Для 95% доверительных интервалов сначала усредняются метрики каждого пользователя, затем 2000 раз одни и те же пользователи выбираются с возвращением для обеих моделей. Начальное значение генератора 2026. Основное сравнение задано для timeSVD++ и ALS, остальные дополнительные.

## Устройство и ресурсы

~~~mermaid
flowchart LR
    A[CSV и метаданные] --> B[Очистка и разбиение по времени]
    B --> C[Отбор пользователей и товаров]
    C --> D[История и признаки]
    D --> E[Обучение моделей]
    E --> F[Отбор top-10]
    F --> G[Метрики и отчёт]
    H[Параметры] --> E
~~~

| Модуль | Что делает |
|---|---|
| `download.py`, `data.py` | Скачивает, очищает и разбивает данные |
| `core.py`, `features.py` | Хранит историю и строит признаки |
| `models/` | Обучает модели и рассчитывает оценки |
| `ranking.py` | Убирает оценённые товары, выбирает рекомендации |
| `metrics.py`, `experiment.py` | Считает метрики, подбирает параметры и ведёт журналы |
| `report.py` | Делает таблицы, графики и примеры |

С весами сохраняется идентификатор каталога, истории и времени запроса. При загрузке совместимость проверяется. Готовые этапы используются только при совпадении данных, параметров, исходников и окружения. Незавершённые и повреждённые файлы отклоняются.

Запуск на процессоре: четыре потока, 31,5 ГиБ памяти, 14 логических ядер. Истории хранятся в CSR/CSC. Одна матрица EASE 7 329 × 7 329 в float64 занимает около 0,400 ГиБ, обучение требует нескольких таких буферов. Оценки каталога считаются группами пользователей. Сохраняются рекомендации и метрики.

FM использует точное разложение признаков на две группы. У timeSVD++ хранятся только наблюдавшиеся пары пользователь-день и товар-период. Модели обучаются по очереди. Версии библиотек указаны в `requirements.lock.txt`. Начальные значения генераторов, версия кода, контрольные суммы, окружение, время и пиковая память записываются в run.json.
