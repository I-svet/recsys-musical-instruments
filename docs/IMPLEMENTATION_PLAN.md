Порядок обязателен: evaluator проверяется до сравнительного обучения, test остаётся вне подбора. В реализации одновременно активен один этап; оптимизации внутри этапа не меняют evaluation protocol.

До тяжёлых экспериментов:

- Уточнить доступную оперативную память и измерить pilot каждого метода.
- Проверить metadata join, не сокращая dataset из-за отсутствующих описаний.
- Убедиться, что выбранная категория не относится к семинарским датасетам.
- Зафиксировать Python и версии зависимостей.

Неопределённости не скрываются:

- Если метрики всех методов низкие, сначала проверяются evaluator и данные; split не меняется ради более красивого результата.
- Если EASE не помещается в память, уменьшаем временные буферы/батчи. Менять каталог можно только как новую явно описанную версию benchmark для всех методов.
- Если timeSVD++ проигрывает, результат сохраняется; абляция помогает понять причину.
- Любое изменение данных, cutoff, relevance, cohort или candidate policy требует новых hashes и полного пересчёта сравнения.

При завершении реализации SYSTEM_DESIGN.md обновляется под фактические решения, а не остаётся описанием первоначального намерения.
