# Персональные top-10 рекомендации: Amazon Musical Instruments 2018

Пять моделей реализованы самостоятельно: ItemKNN, explicit ALS со смещениями, EASE, FM с историческими метапризнаками и causal timeSVD++. Дополнительно реализованы MostPopular, FM только с ID и SVD++ без временных компонент.

Обучение, предсказания, отбор кандидатов и метрики находятся в этом репозитории. NumPy/SciPy используются для линейной алгебры, PyTorch для тензоров, autograd и Adam. Готовых рекомендательных моделей и обучаемых алгоритмов sklearn здесь нет.

Полный эксперимент завершён: 73 конфигурации на validation и 18 финальных прогонов. EASE получил наибольшие NDCG@10 = 0,01411 и Recall@10 = 0,02507. Это описательный результат данного сравнения; доказанного превосходства над всеми моделями он не означает. ItemKNN охватывает 32,16% каталога, EASE — 14,27%, FM — 0,33%. Локально и в CI на Windows/Linux прошли 78 тестов.

## Данные

[Первоисточник: Amazon Review Data 2018, UCSD](https://cseweb.ucsd.edu/~jmcauley/datasets/amazon_v2/). Используется полный файл оценок категории Musical Instruments. Скачивание выполняется командой `python -m recsys download --metadata` с проверкой SHA256 обоих файлов.

Из 1 512 530 строк удаляются 41 966 повторных пар пользователь–товар: сохраняется первый отзыв по времени, при равенстве дат по номеру строки. После глобального временного разбиения выполняется итеративный 5-core только на train. Состав пользователей и товаров фиксируется для всех моделей.

| Часть | Период UTC | Взаимодействия |
|---|---|---:|
| Train | до 2017-04-17 | 144 036 |
| Validation | 2017-04-17 ≤ t < 2017-12-08 | 5 547 |
| Test | t ≥ 2017-12-08 | 3 741 |
| Всего | 17 702 пользователя, 7 329 товаров | 153 324 |

Границы зафиксированы предварительным аудитом по 80-му и 90-му процентилям полной дедуплицированной категории. Все события одного дня остаются вместе. Метаданные дают названия 7 324 товаров; пять отсутствующих описаний не удаляют взаимодействия.

Это benchmark для активных пользователей и фиксированного каталога. В test 1 702 пользователя с положительными оценками внутри каталога. Отдельная `Recall_all_future@10` включает будущие положительные события выбранных пользователей за пределами каталога. Только 57,37% таких событий достижимы внутри выбранного каталога; это покрытие данных, не Recall модели. Категорию нужно сверить со списком семинарских датасетов курса, который не предоставлен.

## Протокол

- Релевантность: будущая оценка ≥4. Все прошлые оценки, включая 1–3, исключают товар из кандидатов.
- Рекомендации выдаются в начале validation/test, без обновления внутри периода. Ранжируется весь каталог, без сэмплирования негативных объектов.
- Основная метрика выбора: macro NDCG@10. Дополнительно считаются Recall@10, Precision@10, MAP@10, покрытие, популярность, RMSE для моделей оценок, время и RSS.
- Параметры выбираются на validation. Финальные модели переобучаются на train + validation с выбранным числом эпох.
- Стохастические модели повторяются с seed 17, 42, 2026. Публикуются mean/std и парные bootstrap-интервалы по пользователям. Детерминированные методы выполняются один раз.
- Пользователи с отсутствующим сигналом или одинаковыми оценками всех кандидатов получают общий popularity fallback; их результаты остаются в сравнении.

FM использует прошлые число и среднее оценок пользователя/товара, возраст истории и календарь запроса. Текущий день исключается из агрегатов, scaling обучается только на fit-части. Поздние названия и категории Amazon используются для отчёта. timeSVD++ содержит временные смещения и дрейф; его неявная история включает только предыдущие дни. Это причинная адаптация исходного метода.

## Установка и воспроизведение

CPython 3.12, CPU. Прямые и транзитивные зависимости зафиксированы в `requirements.lock.txt`. Для обучения желательно 16 ГБ RAM. Измеренная машина имеет 31,5 ГиБ; используются четыре потока. Побитовое совпадение между платформами/версиями BLAS не обещается.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.lock.txt
python -m pip install --no-deps --no-build-isolation -e .
python -m pytest -q
python scripts/reproduce.py
```

Последняя команда скачивает данные, готовит выборку, выполняет pilot/search/refit и строит отчёт. Raw-данные и веса моделей исключены из Git. Промежуточные результаты: `artifacts/benchmark`; ваш повторный отчёт: `reports-local`. Опубликованный эталон находится в `reports` и сохраняется при воспроизведении.

Поэтапный запуск:

```bash
python -m recsys download --metadata
python -m recsys prepare
python -m recsys metadata
python -m recsys run --stage pilot
python -m recsys run --stage tune
python -m recsys run --stage final
python -m recsys report --output reports-local
python scripts/plot_tradeoff.py reports-local
python scripts/verify_report.py reports-local
```

Короткая проверка всего конвейера на той же выборке:

```bash
python scripts/reproduce.py --config configs/smoke.json --output artifacts/smoke --report reports-smoke
```

Smoke выполняет одну конфигурацию и до двух эпох. Его метрики не заменяют полный эксперимент.

Проверка контрольных сумм опубликованного отчёта без скачивания датасета и установки пакетов:

```bash
python scripts/verify_report.py reports
```

Повторный запуск пропускает только завершённые совместимые этапы. Изменение данных, исходного кода, окружения или конфигурации требует нового `--output`; повреждённые файлы отвергаются. Поиск создан `scripts/make_configs.py` с seed 2026 до основного эксперимента: 16 KNN, 8 EASE и по 16 ALS/FM/timeSVD++; ALS до 40 итераций, FM/timeSVD++ до 50 эпох, patience 5. Для каждого факторного метода заданы один опорный набор и 15 случайных. Абляции используют параметры основной модели и собственный validation early stopping; это отключение компонента при фиксированных настройках, а не отдельный полный поиск.

Top-10 для внутреннего ID пользователя:

```bash
python -m recsys recommend --model artifacts/benchmark/final/ease/42/model.pkl --user 0
```

Checkpoint сверяется с каталогом, историей и временем snapshot. Pickle предназначен только для собственных доверенных файлов: загрузка произвольного чужого checkpoint может выполнить код.

## Структура и проверки

```text
src/recsys/
  core.py             # snapshot и контракт модели
  download.py         # источники и SHA256
  data.py             # очистка, временное разбиение, train-only core
  features.py         # причинные признаки FM
  models/classic.py   # MostPopular, ItemKNN, ALS, EASE
  models/fm.py        # FM
  models/timesvd.py   # causal timeSVD++ и SVD++
  ranking.py          # кандидаты, fallback, exact top-k
  metrics.py          # метрики и paired bootstrap
  experiment.py      # search, early stopping, refit, manifests
  report.py           # таблицы, графики и рекомендации
```

Тесты проверяют математические эталоны, ALS objective, причинность признаков и истории, градиенты, равенство прямого и ускоренного scoring, ties на границе top-k, seen-фильтрацию, сериализацию и сквозной эксперимент. Подмена test-данных не меняет выбор на validation. CI проверяет Windows и Linux; полный benchmark запускается явно.

Код распространяется по MIT. Лицензия кода не меняет условия Amazon Review Data. Исходные пользовательские ID, имена и тексты отзывов в публичные результаты не включаются.
